# Repair Pipeline

The benchmark → diagnosis → provable fix workflow.

This is the commercial core of skill-bench.md. Every phase builds evidence
that makes the next recommendation more defensible. The final output — a
`skill-fix-{runId}.md` — is generated from hard data, not opinion.

---

## The 6 Phases

```
Phase 1  routing-flat          baseline routing accuracy
Phase 2  routing-format        format sensitivity diagnosis
Phase 3  loading-progressive   depth/layer compliance
Phase 4  adversarial-overlap   ambiguity and negation robustness
Phase 5  repair recommendation generated from Phase 2–4 evidence
Phase 6  retest after patch    verify the fix with the same suites
```

You do not need to run all 6 phases. Phase 2 alone produces actionable
recommendations. Run more phases when you need higher-confidence evidence
or are diagnosing a specific failure class.

---

## Phase 1 — Baseline

**Suite:** `routing-flat`  
**Output:** `routing-flat-{model}-{timestamp}.csv`  
**What you learn:** Raw routing accuracy. Is the model routing skills at all?

If Phase 1 accuracy < 70%, stop. The model's base routing is broken. Skill
authoring format won't fix a fundamentally unroutable model.

---

## Phase 2 — Format Sensitivity

**Suite:** `routing-format`  
**Output:** `.matrix.csv` + `.recommendation.json`  
**What you learn:** Which prompt format the model responds to reliably.

The `.recommendation.json` artifact contains:

```json
{
  "suite": "routing-format",
  "model": "llama-3.1-8b-instant",
  "provider": "groq",
  "run_id": "2026-04-24T08-00-00",
  "best_format": "described",
  "worst_format": "bare",
  "format_spread_pp": 30,
  "confidence": "high",
  "recommendation": "Model is highly format-sensitive (spread 30pp). All skill files must use described format. Do not ship bare-format skills to this model.",
  "reason": "Described format outperformed bare by +30pp across the same 200 skill IDs (bare 50% → described 80%).",
  "gains": {
    "delimited_vs_bare": 15,
    "described_vs_bare": 30,
    "described_vs_delimited": 15
  },
  "skill_authoring_rule": "Every skill file must include: description, input_type, output_type, and constraints fields.",
  "next_suite": "loading-progressive",
  "paywall_artifact": "skill-fix-2026-04-24T08-00-00.md"
}
```

**`format_spread_pp` interpretation:**

| Spread | Confidence | Meaning |
|---|---|---|
| > 20pp | high | Model is highly format-sensitive. Authoring format is the primary lever. |
| 10–20pp | medium | Format matters but model has some tolerance. Prefer best_format. |
| < 10pp | low | Format-stable. Use bare for token efficiency. |

---

## Phase 3 — Depth Compliance

**Suite:** `loading-progressive`  
**Output:** `loading-progressive-{model}-{timestamp}.csv`  
**What you learn:** Does the model correctly load skill layers at all
depths (1, 2, 3, 5)? Does depth accuracy degrade as layers increase?

If depth accuracy drops sharply at depth 3+, skills need to be
flattened — layer chaining is causing context loss.

---

## Phase 4 — Adversarial Robustness

**Suite:** `adversarial-overlap`  
**Output:** `adversarial-{model}-{timestamp}.csv`  
**What you learn:** Does the model get confused by similar skill IDs,
negation prompts, or ambiguous descriptions? Identifies the specific
lexical patterns that cause routing failures.

---

## Phase 5 — Repair Recommendation

The `skill-fix-{runId}.md` is generated by combining evidence from
Phases 2–4. It is not a generic template — every statement is backed
by a specific data point from the runs.

**Example output for `llama-3.1-8b` with observed data:**

```markdown
# Skill Fix Report — llama-3.1-8b
Run ID: 2026-04-24T08-00-00

## Summary
Your internal skills fail primarily in bare format.
Delimited improves accuracy by +15pp.
Described improves accuracy by +30pp.
Recommendation: convert all skill files to described format.
Expected improvement: +20–30pp based on benchmark data from 200 skills.

## Evidence
- routing-format bare accuracy:      50.0% (100/200 passed)
- routing-format delimited accuracy: 65.0% (130/200 passed)
- routing-format described accuracy: 80.0% (160/200 passed)
- format_spread: 30pp (confidence: HIGH)

## Required Changes
Every skill file must add the following fields:
  description:  <what the skill does, 1–2 sentences>
  input_type:   <what the caller provides>
  output_type:  <what the skill returns>
  constraints:  [<list of hard rules for the output>]

## Verification
After patching, re-run:
  npm run bench:groq:format

Expected new described accuracy: ≥ 85%
Expected new format_spread: < 15pp
```

---

## Phase 6 — Retest

Re-run the same suites from Phases 1–4 after applying the recommended
patches. Compare run IDs.

```bash
# Phase 6 retest — same commands, new run_id
npm run bench:groq:format
npm run bench:groq:progressive
```

If Phase 6 described accuracy >= Phase 2 described accuracy + 5pp,
the fix is verified. If not, escalate to Phase 4 (adversarial) to
identify residual failure patterns.

---

## The Product

The `skill-fix-{runId}.md` artifact is the paid deliverable. It is
valuable because it converts benchmark data into a specific, testable
instruction set:

- Not "your skills might need improvement"
- But "your `llama-3.1-8b` skills fail 50% in bare format; adding a
  description block brings them to 80%; here are the exact fields
  required; here is the retest command to verify."

The evidence trail (run_id chain: Phase 1 → 2 → 6) makes every
recommendation auditable.
